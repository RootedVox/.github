# 双活架构技术白皮书 (ADR-001)

## 背景
为了降低单一云服务商宕机导致瘫痪的风险，同时最大化利用免费的边缘计算额度，本项目引入了 CF 与 Vercel 双活架构。

## 目录结构映射差异
由于两大平台的底层逻辑不同，目录结构必须做出妥协：
- **Cloudflare Pages/Workers**: 后端逻辑通常放置在 `functions/` 目录。
- **Vercel Serverless**: 后端逻辑通常放置在 `api/` 目录。

## 异构同源解决方案
我们在代码中封装了一个被动探针。在用户发起后端请求时，直接向 CF 后端发起请求并抓取返回值，如果抓取到报错或请求超时，自动向 Vercel 后端发起请求。

对于后端逻辑，我们在 `functions/` 和 `api/` 中分别编写代码来实现后端逻辑和对外暴露接口，但两个后端只有少许不同。

## 数据一致性
所有后端节点统一连接至 Supabase 实例。利用 PostgreSQL 自带的事务和并发控制机制保证数据一致性。
